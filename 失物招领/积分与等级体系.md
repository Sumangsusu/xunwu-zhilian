# 寻物智联 · 积分与等级激励体系

> 目标：让「捡到东西并归还」这件事在校园里被看见、被记住。用低门槛的积分与等级，
> 把一次性的善意变成可持续的参与。

## 一、等级设计

注册即 **Lv.0**，积分只增不减、等级只升不降，避免用户因降级而放弃使用。

| 等级 | 称号 | 起始积分 | 视觉 |
| --- | --- | --- | --- |
| Lv.0 | 新同学 | 0 | 🌱 |
| Lv.1 | 热心路人 | 30 | ✨ |
| Lv.2 | 拾物达人 | 80 | 🔍 |
| Lv.3 | 归位能手 | 180 | 🎯 |
| Lv.4 | 校园活雷锋 | 350 | 🏅 |
| Lv.5 | 寻物领航员 | 600 | 🚀 |
| Lv.6 | 珞珈守望者 | 1000 | 🛡️ |
| Lv.7 | 拾光传奇 | 1600 | 👑 |

规则定义在 `points.js` 的 `LEVELS`，前后端（个人中心、积分榜、管理端）共用同一份数据，
改门槛只需改这一处。

## 二、积分获取规则

| 行为 | 积分 | 说明 |
| --- | --- | --- |
| 发布招领启事（捡到东西） | +5 / 条 | 发布成功即时到账 |
| 发布寻物启事 | +2 / 条 | 鼓励失主主动登记 |
| 招领启事成功归还（标记已认领） | +60 | 归还闭环的核心奖励 |
| 寻物启事确认找回（标记已找回） | +15 | 寻物侧的正向反馈 |
| 管理员手动调整 | ±1~500 | 线下表彰、异常刷分扣回 |

**计分上限（防刷）**

- 发布类：寻物 + 招领合计每日最多计分 5 条，超出仍可正常发布，只是不再加分；
- 归还类：每日最多计分 3 次；
- 幂等键 `ref = publish:<启事id> / resolve:<启事id>`，同一启事反复切换状态也只计一次；
- 积分一经发放不自动回收（避免误操作丢分），异常账号由管理员在后台减分并留下流水。

## 四、管理员后台

`/admin` 新增「积分总榜」区块：

- 全体用户按积分排序（含 0 分用户），显示排名、等级、积分、发布数、归还数；
- 支持用户名搜索；
- 每行「调分」按钮：填写 ±1~500 分与备注，写入 `point_events` 流水，便于线下表彰与异常扣回；
- 顶部汇总：总人数、累计发放积分、人均积分、有分用户数、最高分；
- 底部展示最近 8 条积分流水（谁、因为什么、加/减多少分）；
- 「用户数据」表格新增积分列（分数 + Lv），用户详情弹窗展示积分与等级。

## 五、接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/points/me` | 登录 | 我的积分、等级、排名、最近流水、规则 |
| GET | `/api/points/leaderboard?limit=n` | 公开 | 排行榜（只列有积分或有发布的参与者；登录时附带我的排名） |
| GET | `/api/admin/points` | 管理员 | 全体用户总榜 + 发放统计 + 最近流水 |

`/api/auth/me`、`/api/auth/login`、`/api/auth/register` 的 user 对象已附带
`points` 与 `level`，前端无需额外请求即可显示等级。

## 六、数据表

```sql
-- 积分流水（唯一事实来源）
CREATE TABLE point_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  delta INTEGER NOT NULL,
  reason TEXT NOT NULL,          -- publish_found / publish_lost / resolve_found / resolve_lost / admin_adjust
  detail TEXT DEFAULT '',
  ref TEXT,                      -- 幂等键
  created_at INTEGER NOT NULL,
  UNIQUE(username, ref)
);

-- users 新增冗余缓存列（由流水汇总，便于排序）
ALTER TABLE users ADD COLUMN points INTEGER NOT NULL DEFAULT 0;
```

`users.points` 由 `SUM(point_events.delta)` 重算，任何调分都可通过流水审计与还原。
服务启动时会做一次**历史回填**（`points.backfill`）：按已有启事补算发布分与已解决分，
幂等执行，生产环境首次上线后老用户也能带着历史贡献上榜。

## 七、验收要点

1. 注册新账号 → 等级 Lv.0 / 0 分；
2. 发布招领 → +5，个人中心与导航等级同步更新；
3. 标记已认领 → +60，重复标记/反复切换不重复加分；
4. 同日第 4 次归还 → 提示「今日归还计分已达上限」，不加分；
5. 积分榜页面公开可看，登录用户高亮「我」；
6. 管理员后台可看全体用户总榜、搜索、调分，调分后榜单与用户表实时刷新。
